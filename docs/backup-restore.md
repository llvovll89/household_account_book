# 전체 백업·복원

사용 가이드 → **전체 백업·복원**에서 저장된 가계부를 JSON으로 다운로드하거나 같은 형식의 파일로 복원한다. 로그아웃 상태에서는 이 기기, 로그인 상태에서는 표시된 계정이 대상이다.

백업에는 거래 내역(태그·결제수단·대출 원금/이자·영수증 URL 포함), 메모, 기본/월별 예산과 이월 설정, 정기 내역, 구독, 저축 목표, 모든 `AppSettings` 항목이 포함된다. 영수증 이미지 바이너리, 인증 정보, 원격 버전 번호, 설치 상태, 기기별 테마와 사용 통계는 포함하지 않는다. 영수증 링크는 기존 저장소의 접근 권한과 파일 수명에 따른다.

파일은 `format: balance-plan-backup`, `version: 1`, `createdAt`, `data` 구조이며 최대 10MB다. 업로드 때와 실제 적용 직전에 알려진 필드만 재구성한다. 모든 컬렉션과 설정이 있어야 하며, 잘못된 날짜·열거형·금액·중복 ID·동일 카테고리/월 예산은 거부한다. 복원 미리보기는 읽기만 수행한다. 현재/복원 후의 개수와 주요 설정, 대상 저장소를 확인하고 전체 교체에 동의해야 적용할 수 있다. 현재 내용을 보관하려면 먼저 백업을 다운로드한다.

기기 복원은 미리보기 때의 원본 저장소 값이 바뀌지 않았는지 확인한다. 여러 키를 쓰기 전에 원본을 복구 저널에 보관하며, 저장 실패 시 원본으로 되돌린다. 중단 후 남은 저널은 다음 읽기/쓰기 전에 복구한다. 저널을 저장할 공간이 없으면 원본 변경 없이 중단한다.

계정 백업은 서버에서 한 문서를 읽으며 오프라인 캐시로 조용히 대체하지 않는다. 계정 복원은 미리보기 때의 7개 버전과 내용, 현재 계정을 확인하고 Firestore 트랜잭션 하나로 전체 컬렉션과 설정 맵을 교체한다. 다른 기기의 변경, 미동기화 내역, 진행 중인 저장이 있으면 중단한다. 실패한 복원으로 `hb_pending_sync`를 만들지 않는다. 원격 반영 후 기기 캐시만 저장하지 못했다면 계정 복원 성공과 캐시 저장 실패를 구분해 안내한다.

검증: 모든 선택 필드와 설정의 파일 왕복, 잘못된 파일/값, 변경된 미리보기, 계정 변경, 로컬 중간 실패/저널 공간 부족/중단 복구, 원격 충돌/오프라인/캐시 실패/동시 저장, 미리보기와 명시적 동의, 취소 및 다운로드를 테스트한다. 실제 계정 데이터는 검증 목적으로 덮어쓰지 않는다.

참고: [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions). 병합 필드의 동작은 설치된 Firebase SDK의 `SetOptions` 문서와 타입에 맞췄다.
