# 사용 흐름 측정

사용 가이드 → 사용 패턴 보기에서 이 기기의 입력·가져오기 흐름을 확인한다. 측정은 기본으로 켜져 있으며 같은 화면에서 중지하거나 삭제할 수 있다. 중지 전 기록은 유지된다. 거래 데이터와 측정 기록은 별도로 저장한다.

## 기록 범위

- 신규 입력 창과 가져오기 창의 시작, 단계 이동, 저장 요청, 저장 성공, 오류, 완료 전 닫음.
- 임의로 생성한 흐름 ID, 흐름 종류, 정해진 단계·이벤트 이름, 시각만 기록한다.
- 금액, 적요, 카테고리, 파일명, 계좌·카드 정보, 사용자 ID를 전달하거나 보관하지 않는다.
- 기존 거래 수정은 신규 입력 완료율에서 제외한다. 연속 입력 여러 건을 한 번에 저장하면 하나의 입력 흐름으로 집계한다.
- 측정 데이터는 localStorage의 `hb_usage_flow_v1`에만 저장한다. Firebase나 외부 분석 서비스로 전송하지 않는다.
- 측정 데이터를 읽거나 추가할 때 최근 30일·최대 600개 이벤트로 정리한다. 브라우저를 사용하지 않는 동안 별도 백그라운드 삭제 작업은 실행하지 않는다.

## 지표 해석

- 기간: 최근 7일 또는 28일 안에 시작한 흐름을 기준으로 집계한다.
- 완료: 저장 계층의 쓰기 성공 후 집계한다. 버튼 클릭만으로 완료 처리하지 않는다.
- 완료 전 닫음: 모달이 닫히거나 페이지가 떠날 때 저장 요청 전이면 집계한다. 브라우저 강제 종료 등 확인할 수 없는 경우는 미완료로 남을 수 있다.
- 미완료·저장 대기: 시작했으나 성공 또는 닫음을 확인하지 못한 흐름이다. 이를 전부 이탈로 해석하지 않는다.
- 오류: 입력 검증·파일 해석·컬럼 확인·저장 중 오류가 있던 흐름 수다. 같은 흐름에서 여러 오류가 나도 한 번 집계한다.
- 재시도해 성공하면 완료와 오류 양쪽에 포함될 수 있다. 같은 저장 성공을 중복 집계하지 않는다.
- 소요시간 중앙값: 시작부터 저장 성공까지 경과한 시간이며, 파일 처리·네트워크 대기·사용자가 창을 열어둔 시간도 포함한다.
- 기록을 완료한 날: 포함된 흐름 중 완료 이벤트가 발생한 서로 다른 기기 현지 날짜 수다. 전체 사용자 재방문율이나 D7 리텐션 지표가 아니다.
- 최대 이벤트 수 때문에 시작 이벤트가 삭제된 흐름은 집계에서 빠진다. 측정 중지·삭제·저장 공간 부족·다른 기기 사용도 수치에 영향을 준다.

요약 내보내기는 위 집계만 JSON으로 내려받는다. 흐름별 ID나 개별 이벤트 목록은 포함하지 않는다. 측정 실패가 기록·가져오기를 막지 않도록 저장소 오류를 처리한다.

## 검증

회귀 테스트는 React StrictMode 중복 시작, 저장 전 닫기, 제출 후 모달 닫기, 실제 저장 실패·재시도, 가져오기 단계, 측정 중지·삭제, 잘못된 저장 데이터, 보관 범위, 요약 내보내기를 다룬다. 실제 전체 사용자 통계를 얻으려면 별도의 수집 범위·동의·서버 분석 설계가 필요하다.
