# 잔고플랜 UI/UX 점검 (2026-10-19)

## 전체 개선 반영 결과

사용자의 전체 적용 요청에 따라 아래 개선을 구현했다. 이후의 우선순위 표는 최초 점검 당시의 문제와 제안이다.

| 항목 | 반영 내용 |
| --- | --- |
| 저장 접근성 | 거래 입력의 저장·계속 입력 버튼을 내용 스크롤 밖에 고정했다. visualViewport 변경에 맞춰 모달 높이를 조정하고 하단 안전 여백을 반영한다. |
| 계좌이체 | 기본 결제수단에 계좌이체를 추가하고 이름을 붙인 자동이체 계좌를 관리할 수 있다. 거래 입력·수정·상세·필터·결제수단 집계·내보내기에 반영한다. |
| 정기 내역 | 신규 항목과 기존 항목 모두 결제수단을 지정할 수 있다. 반복 적용 시 계좌 ID와 카드 결제일을 보존한다. 구형 항목은 기존 현금 기본값을 유지한다. 빈 화면의 중복 추가 버튼도 제거했다. |
| 안전한 카테고리 삭제 | 거래·정기 내역·템플릿·자동 분류·예산·구독·목표 연결 건수를 미리 보여준다. 이동 대상을 고르고 저장할 때 적용한다. 삭제 취소와 저장 없이 닫기를 제공하며, 같은 월 예산은 한도를 합쳐 보존한다. |
| 유출 분석 | 선택 월의 전체 유출·소비·저축·대출 상환을 전환해 볼 수 있다. 기존 총액과 원본 기록은 유지한다. 보험료는 소비에 포함한다. |
| 대출 구분 | 대출 거래에서 원금·이자를 선택 입력하고 합계가 거래 금액과 일치하는지 검사한다. 상세 화면과 분석에서 확인할 수 있으며, 구분 없는 과거 기록은 미구분 금액으로 표시한다. |
| 카테고리 탐색 | 이름 검색, 최근 사용 항목, 검색 결과 없음 안내를 추가했다. 긴 이름을 줄임표 대신 줄바꿈으로 보여주고 전체 목록 순서는 유지했다. 최근 사용 집계는 거래를 한 번 순회한다. |
| 저장 문구 | 대기열 추가를 '계속 입력', 실제 저장을 '저장'으로 구분하고 '저장 전 N건'을 표시한다. |
| 접근성·테마 | 카테고리·결제수단 관리에 모달 역할·포커스 제한·Escape·복귀 포커스를 적용하고 입력 레이블과 오류 안내를 연결했다. 날짜 버튼·차트 공용 색·카테고리 색에 두 테마의 의미 토큰을 적용했다. |

실제 계정 데이터의 자동 재분류나 일괄 변경은 실행하지 않았다. 사용자가 카테고리 이동을 선택한 뒤 저장해야 기록을 옮긴다. 부채 잔액 추적 기능은 이번 범위에 포함하지 않는다.

## 전체 개선 검증

- 전체 lint, 기존·신규 테스트 88개, 프로덕션·PWA 빌드 통과. 이후 정기 내역 UI 보완은 별도 lint·추가 테스트 1개·프로덕션 빌드로 재확인했다. 검증된 테스트는 총 89개다.
- 저장 호환성: 계좌이체, 계좌 ID, 대출 원금·이자, 정기 내역을 저장 후 다시 읽는 테스트와 기존 기록 호환성 확인.
- 연결 데이터: 카테고리 이동 시 거래·반복 내역·구독·목표를 옮기고 예산 한도를 보존하는 통합 테스트. 정기 적용에서 계좌 ID가 유지되고, 계좌이체가 카드 청구에 들어가지 않는 테스트 포함.
- 별도 브라우저에서 390×844 모바일과 1440×1000 데스크톱, 라이트·다크 모드 확인. 대출 110,000원을 계좌이체로 기록하고 수정에서 원금 100,000원·이자 10,000원을 저장한 뒤 분석 반영 확인.
- 카테고리 관리에서 새 항목 추가·삭제 영향 미리보기·삭제 취소·Escape 닫기 확인. axe-core 모달 검사: 위반 0건, 추가 수동 확인 항목 0건.
- 390×520 작은 뷰포트에서도 거래 입력의 저장 버튼 노출 확인. 거래 입력 모달 axe-core 검사도 위반 0건, 추가 수동 확인 항목 0건. 정기 보험료 50,000원을 계좌이체로 등록하는 브라우저 흐름 확인.
- 프로덕션 홈의 Lighthouse 모바일 시뮬레이션: 접근성 100점, 성능 63점, LCP 7.0초, CLS 0, TBT 340ms. 초기 로딩 성능은 목표에 미달하며, 기존 공용 번들의 사용하지 않는 JavaScript와 렌더링 차단 요청 최적화가 추가로 필요하다. 이 수치는 새 모달의 입력 응답 시간이나 실제 기기의 INP 측정값을 의미하지 않는다.
- 실제 휴대폰 가상 키보드와 Firebase 계정 동기화는 별도 실기기·계정 검증이 필요하다. 로컬 브라우저 창 크기 변경은 실제 키보드 검증을 대체하지 않는다.

## 범위와 방향

지출 기본 카테고리 확장과 일상적인 기록 흐름을 점검하고 개선했다. 기존 UI를 유지하는 개선이다. 기존에 수정 중이던 UX_REVIEW.md는 변경하지 않았다.

- 대상: 수입과 지출을 빠르게 기록하고 월별 현금 흐름을 확인하는 개인 사용자.
- 유지: 잔고플랜 브랜드, Pretendard, 데스크톱 사이드 메뉴/모바일 하단 메뉴, 라이트/다크 모드, 파란 주요 동작과 수입·지출 의미 색상.
- 기존 토큰: 다크 배경 `#131619`, 표면 `#1c2024`, 높은 표면 `#272d33`, 본문 `#edf0f3`, 보조 문구 `#a4adb7`, 주요 버튼 `#356bb3`. 라이트 모드 토큰은 기존 interface.css를 따른다.
- 형태: 패널 18px, 조작 요소 10px, 배지 6px. 텍스트와 필드는 왼쪽 정렬, 금액은 오른쪽 정렬.
- 기준: DESIGN_VARIANCE 3 / MOTION_INTENSITY 2 / VISUAL_DENSITY 5. 금융 기록에서는 예측 가능한 배치와 정확한 피드백을 우선한다.
- 검토 결과: 마케팅용 큰 제목, 사진, 장식, 새 컴포넌트 시스템 도입은 이번 작업에 필요하지 않다. 기존 React/Tailwind와 Lucide를 유지한다. design-taste-frontend의 랜딩 페이지 규칙은 제품 입력 UI에 기계적으로 적용하지 않는다.
- 정보 구조, 경로, 내비게이션, 로고, 필드 순서와 SEO 메타는 변경하지 않는다.

## 이번에 반영한 내용

- 지출 기본 카테고리에 **대출**, **보험** 추가. 거래 입력, 예산, 정기 내역, 자동 분류 규칙, 구독, 목표 연계, 일괄 카테고리 변경에서 공유하는 기본 목록에 반영했다.
- 새 항목의 아이콘·색상·기존 화면용 이모지 제공. 아이콘을 배열 순서가 아닌 카테고리 이름에 연결해 기존 항목이 바뀌는 문제를 예방했다.
- 기존 사용자가 같은 이름을 직접 추가했더라도 거래 입력·예산·정기 내역·자동 분류에서 한 번만 표시한다. 카테고리 관리에서도 기본 목록에만 표시한다. 저장된 사용자 카테고리 이름은 보존해 기존 거래·규칙을 삭제된 카테고리로 오인하지 않도록 했다.
- 가져오기 추천에서 보험을 저축과 분리했다. 보험·대출 키워드를 일반 주거·의료 키워드보다 먼저 확인한다.
- 입금은 수입 카테고리, 출금은 지출 카테고리 안에서 추천한다. 보험 환급금·대출 입금은 지출 보험·대출로 분류하지 않고 기타수입으로 제안한다.
- 과거 거래의 카테고리는 자동 변경하지 않는다. 이번 분류 수정은 앞으로 가져오는 내역의 추천에 적용한다.

대출은 가계부의 출금 분류다. 원금·이자 선택 입력과 저축·대출을 분리해 보는 분석을 제공하며, 부채 잔액 자체는 추적하지 않는다.

## 제안하는 입력 화면 구조

기존 필드 순서를 유지하면서 저장 동작만 스크롤 영역 밖으로 꺼내는 안이다.

```text
내역 추가                              닫기
------------------------------------------
스크롤 영역
  수입 / 지출
  결제수단
  금액 / 날짜
  카테고리
  메모 / 선택 옵션
------------------------------------------
저장 전 N건             계속 입력 | 저장
```

## 카테고리 추가 단계 검증 (이전 작업)

- lint와 전체 테스트 76개 통과. 새 테스트의 TypeScript 옵션 오류 수정 후 `npm.cmd run build:verify` 재실행으로 타입 검사·프로덕션 빌드·PWA 생성 통과. `git diff --check` 통과.
- 빌드에는 기존 Browserslist 데이터 갱신 안내가 남아 있다.
- 별도 로컬 브라우저 세션에서 거래 입력과 새 카테고리 표시 확인.
- 390×844 라이트 모드에서 보험 150,000원을 선택·저장하고 홈의 지출 합계 및 보험 표시 반영 확인.
