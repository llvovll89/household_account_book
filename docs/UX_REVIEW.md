# 가계부 UI·UX 개선 기록

## 디자인 방향

기존 다크 테마와 잔고플랜 브랜드를 유지하면서 토스 앱에서 참고한 금액 중심의 위계, 중립적인 카드 표면, 명확한 주요 행동을 강화했다. 토스 공식 컴포넌트를 적용한 앱은 아니며 기존 React/Tailwind 컴포넌트를 개선했다.

참고: [토스 사용자 관점](https://toss.tech/article/thinking-user-perspective), [토스 디자인 시스템 운영](https://toss.tech/article/toss-design-system).

## 발견한 문제와 반영 내용

| 문제 | 반영 |
| --- | --- |
| 홈에서 보조 위젯이 핵심 잔액보다 먼저 나옴 | 월별 요약을 최상단으로 이동하고 기록 버튼 배치 |
| 요약 카드 안에 소비 비율·카테고리·카드 청구 정보가 한꺼번에 노출됨 | 상세 정보를 접고 필요할 때 펼쳐보도록 구성 |
| ‘이번 달 잔액’이 실제 계좌 잔액처럼 읽힐 수 있음 | 선택한 월과 수입−지출 기준을 명시 |
| 기록 없음이 무지출 확정처럼 표현됨 | 오늘 지출 안내를 기록 여부에 맞게 수정하고, 거래 없는 달의 요약 배지 숨김 |
| 검색창이 상세 필터 안에 숨겨짐 | 목록에서 검색을 항상 노출하고 검색·지우기 회귀 테스트 추가 |
| 모바일 필터의 sticky 위치가 상단 헤더와 겹칠 수 있음 | 중복 고정 제거 |
| 입력 화면만 보라색 계열 배경과 수입·지출별 다른 저장 버튼 색을 사용 | 중립적인 다크 표면과 파란 저장 버튼으로 통일 |
| 핵심 화면의 보조 문구가 배경에 비해 어두움 | 홈·내역·입력·빈 상태의 회색 문구 대비 강화 |
| 월 이동 버튼과 하단 플로팅 버튼의 터치 영역·위치가 불안정함 | 월 이동 버튼 44px, 하단 안전 여백과 내비게이션 높이 정리, 추가 버튼에 텍스트 표시 |
| 금액 입력의 접근 가능한 이름 누락 | 원 단위 이름과 금액 오류 시 포커스 제공 |

## 검증 및 남은 확인

- 프로덕션 빌드 통과.
- 기존 테스트 51개와 새 검색 회귀 테스트 1개 통과.
- 전체 lint에서는 18개 오류와 9개 경고가 보고됨. 분석 화면, 차트, PWA, 파서 등의 별도 코드 정리가 필요함.
- 브라우저 자동화 CLI가 설치되어 있지 않고 연결 가능한 브라우저도 없어 스크린샷과 실제 터치·키보드 동작은 검증하지 못함. 390px 모바일에서 하단 버튼·키보드·긴 금액, 데스크톱에서 카드와 모달을 확인해야 함.
- 거래 데이터와 저장 형식은 변경하지 않음. 기존 useModalClose.ts 작업은 보존함.


## 추가 안정성 개선 (2026-09-11)

- 홈·분석의 6개월 통계를 선택한 월 기준으로 통일하고 단일 순회로 집계한다.
- 월별 예산은 기본 예산보다 우선 적용한다. 분석에서 다른 월의 예산이나 기본값을 중복 합산하지 않으며, 로그인 병합에서도 기본 예산과 월별 설정을 각각 보존한다.
- 월말 정기내역 적용 시 2월 31일처럼 존재하지 않는 날짜를 해당 월의 마지막 날로 보정한다.
- 저장 공간 부족 오류를 호출자에게 전달해 실패 안내와 재시도가 가능하도록 한다.
- 필터·검색·정렬·금액 범위 변경 시 목록 페이지를 초기화하고 삭제 대기 항목의 변경도 즉시 반영한다.
- 거래 입력의 카테고리 선택을 유지하고 수입·지출 전환 시 유효한 카테고리로 보정한다.
- 도넛 차트 데이터 축소 시 선택 인덱스 오류를 방지하고 연간 차트의 ‘월월’ 표기를 수정한다.
- 누적 잔액 계산의 반복 순회를 줄이고 내보내기 시 원본 거래 배열을 정렬하지 않도록 수정한다.
- React 상태·의존성 및 파서 정규식 오류를 정리했다. lint 규칙은 유지한다.
- `npm run verify`에서 lint → 테스트 → 검증 빌드를 실행한다. Unix 전용 삭제 명령을 제거하고 `dist2`를 Git과 lint 검사에서 제외한다.

### 추가 검증

- 테스트 61개: 월말·윤년, 월 선택/연도 전환, 월별 예산 우선순위/병합 보존, 저장 공간 부족, 거래 입력·카테고리 전환 포함.
- lint 오류·경고 0개 및 프로덕션 검증 빌드 통과.
- 별도 브라우저 세션에서 홈 및 거래 입력 모달을 열고 390×844 모바일 화면에서 금액 입력과 스크린샷을 확인했다. 이후 브라우저 자동화 연결이 시간 초과되어 전체 탭 탐색·저장 흐름은 브라우저에서 완료하지 못했다. 거래 저장 흐름은 컴포넌트 테스트로 확인했다.
- 실제 Firebase 계정의 로그인·동기화와 휴대폰 PWA 설치는 이번 검증에 포함하지 않았다.
- 빌드에 Browserslist 데이터 갱신 안내가 남아 있다.
