# 가져오기·내보내기·태그·영수증 수정

- 날짜: 2026-11-09
- PR: #30 / 커밋: `21619f0`

## 한 줄 요약
은행 파일의 금액·날짜·입출금 구분을 잘못 읽던 문제, CSV 수식 주입, 태그 변경이 되돌아가던 문제, 영수증 업로드가 끝나지 않던 문제를 고쳤습니다.

## 왜 했나
입력·가져오기 리뷰에서 8건을 찾았고 재현했습니다.
- `+2,500,000` 급여가 지출로 들어갔고, `15000.00`은 100배인 1,500,000원으로 읽혔습니다. 전각 숫자가 든 행은 조용히 빠졌습니다.
- 구분 값에 `입` 한 글자만 있어도 수입으로 판정해서 `카드구입`이 수입으로 들어갔습니다.
- 출금 컬럼만 있는 카드 내역은 매핑 검증을 통과해 놓고 "파싱된 내역이 없습니다"가 떴습니다.
- 날짜가 셀 형식으로 저장된 xlsx는 모든 행이 버려졌습니다. `2024.3.5`처럼 월·일이 한 자리인 날짜도 빠졌습니다.
- 앱에서 내보낸 CSV를 다시 가져오면 수입이 지출로 바뀌고 설명이 비었습니다. 보관(아카이브)한 데이터를 복구할 유일한 경로가 오염되는 문제였습니다.
- CSV 내보내기에서 `=HYPERLINK(...)`처럼 수식으로 시작하는 설명이 Excel에서 실행될 수 있었습니다.
- 태그를 삭제하거나 이름을 바꿔도 그 내역을 다시 수정하면 이전 태그가 되살아났습니다. 이름을 합치면 통계가 2배로 잡혔습니다. `#c++` 같은 태그는 지울 때 오류가 났습니다.
- 영수증 파일을 읽지 못하면 업로드가 끝나지 않고 계속 대기했습니다.

## 무엇을 바꿨나
- 금액: 부호, 소수, 괄호 음수, 전각 숫자, 통화 기호를 처리하고 원 단위로 반올림합니다.
- 금액 컬럼 하나만 있는 파일은 **음수가 하나라도 있을 때만** 부호로 수입·지출을 나눕니다. 지출을 양수로 적는 카드 명세서는 지금처럼 지출로 처리합니다.
- 구분 값이 `입금`, `수입`, `credit`, `deposit`으로 시작할 때만 수입으로 봅니다.
- 입금이나 출금 컬럼 한쪽만 매핑해도 가져옵니다. 한 자리 월·일과 xlsx 날짜 셀도 읽습니다.
- `유형`과 `설명` 헤더를 자동으로 인식해서, 앱에서 내보낸 CSV를 그대로 다시 가져올 수 있습니다.
- CSV에서 수식으로 해석될 수 있는 셀 앞에 `'`를 붙입니다. 다운로드 URL은 바로 해제하지 않고 1초 뒤에 해제합니다(Safari/iOS PWA 대응).
- 태그를 바꾸거나 지우면 설명 속 `#태그`도 함께 바꾸고, 중복을 제거합니다. 특수문자가 든 태그도 안전하게 지웁니다.
- 영수증을 읽거나 압축하는 데 실패하면 오류로 끝납니다.

- xlsx 0.18.5와 0.20.3 양쪽에서 날짜 셀 처리 API가 동작하는지 직접 실행해 확인했습니다.
