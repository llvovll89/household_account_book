# PDF 명세서 가져오기가 동작하지 않던 문제 수정

- 날짜: 2026-11-23
- PR: #41

## 한 줄 요약
PDF 가져오기가 항상 실패하던 문제, 페이지당 1건만 읽던 문제, 금액 자리에 연도(2026)가 들어가던 문제를 고쳤습니다.

## 왜 했나
code-review(xhigh)에서 PDF 경로가 3단계 모두 막혀 있음을 확인했습니다.
- **항상 실패:** 설치된 `pdfjs-dist`는 5.5.207인데 워커는 CDN 4.4.168로 고정돼 있었습니다. 버전 검사에서 `getDocument`가 바로 실패했습니다.
- **페이지당 1건:** 페이지의 텍스트 조각을 모두 공백으로 이어 붙여서 페이지 하나가 한 줄이 됐습니다. 줄 단위 파서는 첫 날짜 하나만 찾았습니다.
- **금액 오류:** 날짜가 든 줄 전체에서 숫자를 찾아서 `YYYY`가 첫 금액이 됐습니다. 기존 테스트는 날짜만 확인해서 놓쳤습니다.

## 무엇을 바꿨나
- 워커를 패키지에서 `?url`로 불러와 항상 같은 버전을 씁니다. 외부 CDN 의존도 없어졌습니다.
- 같은 y좌표의 조각끼리 한 줄로 묶습니다(`joinPDFTextItems`).
- 금액은 줄에서 날짜를 지운 뒤 찾습니다.

## 확인한 방법
- 두 줄짜리 페이지에서 2건과 올바른 금액이 나오는 테스트를 추가했습니다.
- `npm run verify` 통과(테스트 272개)
- 빌드 결과
  - 워커는 `assets/pdf.worker.min-*.mjs`(1.2MB)로 따로 나옵니다.
  - PWA precache 패턴(`*.js`)에 걸리지 않아 설치 용량은 늘지 않습니다.
  - PDF를 고를 때만 내려받습니다.

## 남은 일·주의
- 은행마다 PDF 레이아웃이 달라 파싱은 여전히 best-effort입니다. 실제 명세서로 한 번 확인해 주세요.
- y좌표가 1pt 이상 어긋난 같은 행은 두 줄로 나뉠 수 있습니다.
