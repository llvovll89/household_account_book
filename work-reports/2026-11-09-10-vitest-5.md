# vitest 5 업그레이드와 CI Node 22 전환

- 날짜: 2026-11-09
- PR: #37

## 한 줄 요약
테스트 도구 체인에 남아 있던 critical 경고를 없애려고 vitest를 3에서 5로 올리고, 지원이 끝난 Node 20 대신 Node 22로 CI를 돌리게 했습니다.

## 왜 했나
- 기술부채 감사 7번(의존성) 중 우선 처리할 항목입니다.
- vitest 3의 의존성(`tinypool`, `@vitest/mocker`)에 critical 1건과 moderate 경고가 남아 있었습니다(#27에서 dev 전용이라 보류했던 항목).
- vitest 5는 Node 22.12 이상이 필요합니다. 그런데 CI(`verify.yml`)는 **2026년 4월에 지원이 끝난 Node 20**을 쓰고 있었습니다.

## 무엇을 바꿨나
- `vitest` 3.2 → 5.1. 설정 파일(`vitest.config.ts`)은 그대로 호환돼서 수정하지 않았습니다.
- CI의 Node 버전을 20 → 22로 올렸습니다(로컬 22.18과 일치).

## 확인한 방법
- 테스트 262개가 모두 그대로 통과했습니다. `npm run verify`(lint, 테스트, 빌드, 시작 번들 예산)도 통과했습니다.
- `npm audit`에서 critical이 0건이 됐습니다(`tinypool`, `@vitest/mocker` 경고 해소).

## 남은 일·주의
- **`npm audit fix`를 쓰지 않은 이유:** 처음에 `npm audit fix`를 돌렸더니 grpc 경고를 고치려고 **firebase까지 12.11 → 12.19로 함께 올렸고**, 홈 첫 화면 번들이 221KB에서 282KB로 커져 시작 번들 예산 검사가 실패했습니다. 그래서 lockfile을 되돌리고 vitest만 올렸습니다. firebase 업그레이드는 번들 크기를 따로 확인하면서 별도 작업으로 진행해야 합니다.
- 남은 경고는 앱 번들에 포함되지 않는 것들입니다.
  - high: `@grpc/grpc-js`(Firestore의 Node 빌드 전용, 최신 firebase도 같은 버전 범위)
  - moderate/low: `workbox-build`(PWA 빌드 도구), `typescript-eslint`(lint 도구)
  - npm이 제안하는 수정은 오히려 구버전으로 내려가는 것이라 적용하지 않았습니다.
- 이 작업 중 `node_modules` 안의 `lightningcss` 파일이 다른 프로세스에 잠겨 있다는 경고(`EPERM`)가 나왔습니다. 빌드와 테스트에는 영향이 없었습니다.
