# 테마 토큰 4단계: 나머지 전부 + 액션 버튼 토큰

- 날짜: 2026-11-23
- PR: #48

## 한 줄 요약
남아 있던 파일 45개의 hex 색상 클래스를 모두 테마 토큰으로 바꿨습니다. 액션 버튼용 `bg-action` / `text-on-action` / `hover:bg-action-hover` 토큰도 추가했습니다. 이제 `src` 어디에도 hex 색상 클래스가 없고, ESLint가 전체 파일에서 재발을 막습니다.

## 왜 했나
- 테마 토큰 작업의 마지막 단계입니다.
- 액션 버튼은 `interface.css`가 `bg-[#3D8EF8]` 같은 클래스를 찾아 배경·글자색·hover를 한꺼번에 바꾸던 구조라서, 전용 토큰이 필요했습니다.

## 무엇을 바꿨나
- `@theme`에 `action-hover`, `on-action`을 추가했습니다(`action`은 이미 있었음).
- 스크립트로 나머지 파일을 치환하고, 표에 없던 색 20여 종은 가장 가까운 토큰으로 정했습니다.
- 액션 버튼 변환
  - `bg-[#3D8EF8]`·`bg-[#3182F6]`·`bg-[#244268]` → `bg-action text-on-action`
  - `hover:bg-[#5AA0FF]` 등 → `hover:bg-action-hover`
  - 같은 문자열의 `text-white`는 지웠습니다. 예전에는 `interface.css`가 버튼 글자색을 `--on-action`으로 덮어써서 `text-white`가 효과가 없었습니다. 그런데 남겨두면 라이트 모드에서 `text-white`가 어두운 글자로 바뀌어 버튼 글자가 어둡게 됩니다.
  - 조건부 클래스라서 `text-white`가 다른 분기에 있던 2곳(새 내역 버튼, 저장 버튼)은 직접 옮겼습니다.
- `interface.css`의 버튼 hover 규칙에 `bg-action`을 추가해, hover 클래스가 없던 버튼도 예전처럼 hover 색이 바뀌게 했습니다.
- ESLint 토큰 규칙을 `src/**/*.tsx` 전체로 넓히고, 액션 색 예외를 없앴습니다. CLAUDE.md 규칙도 갱신했습니다.

## 확인한 방법
- `npm run verify` 통과(테스트 279개)
- `src`에 hex 색상 클래스 0건(grep으로 확인)
- 캡처 비교는 하지 못했습니다.
