# 작업 보고서

커밋(PR) 하나마다 보고서 하나를 남깁니다. 무엇을 왜 바꿨고 어떻게 확인했는지를 코드를 열지 않고도 알 수 있게 쓰는 것이 목적입니다.

## 작성 규칙

- 파일명: `YYYY-MM-DD-NN-주제.md` (NN은 같은 날짜 안의 순번)
- 보고서는 해당 작업 PR 안에 함께 커밋하고, 아래 목록에 한 줄을 추가합니다.
- 형식:

```md
# 제목

- 날짜 / PR / 커밋

## 한 줄 요약
## 왜 했나        — 사용자가 겪던 문제, 근거(측정·재현)
## 무엇을 바꿨나  — 사용자 관점의 변화 위주, 필요한 만큼만 파일 언급
## 확인한 방법    — 테스트, 측정, 수동 확인
## 남은 일·주의   — 배포 후 할 일, 의도적으로 하지 않은 것
```
