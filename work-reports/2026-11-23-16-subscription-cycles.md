# 구독: 연간 결제와 USD 환율

- 날짜: 2026-11-23
- PR: #54

## 한 줄 요약
구독에 '매년' 결제 주기를 추가했고, 환율을 입력하면 USD 구독도 원화 합계에 들어갑니다.

## 왜 했나
기능 분석 F6 항목입니다.
- 결제 주기가 월간뿐이라 연간 결제 구독(도메인, 연간 멤버십 등)을 제대로 적을 수 없었습니다.
- USD 구독은 월 합계·연간 합계·절감 시뮬레이터에서 모두 빠졌습니다.
- 결제 예고는 매월만 가정해서 계산했습니다.

## 무엇을 바꿨나
- **데이터:** `Subscription`에 `cycle`(`monthly`|`yearly`, 없으면 매월)과 `billingMonth`(1~12)를 추가했습니다. 설정에는 `usdKrwRate`를 추가했습니다. 백업 스키마와 병합에도 반영했습니다.
- **계산:** `lib/subscriptions.ts`를 추가했습니다.
  - `getDaysUntilNextBilling`: 연간 구독은 결제 월·일 기준으로 셉니다. 없는 날짜는 말일로 맞춥니다.
  - `getMonthlyKrw`: 연간 금액은 12로 나누고, USD는 환율이 있을 때만 원화로 바꿉니다.
  - `getSubscriptionTotals`: 월·연간 원화 합계를 내고, 환율이 없어 합계에서 빠진 USD는 따로 냅니다.
- **구독 화면**
  - 입력: '매월 | 매년' 토글과 결제 월 선택을 추가했습니다.
  - 목록: '매년 3월 1일'처럼 표시합니다.
  - USD 구독이 있으면 '환율 1달러 = ○원' 입력을 보여줍니다. 입력칸에서 벗어나면 저장됩니다.
  - 카테고리 분포와 절감 시뮬레이터도 월 환산 원화 기준으로 계산합니다.
- **홈·월간 대시보드:** 구독 결제 예고가 같은 함수를 씁니다. 그래서 연간 구독은 결제 월에만 예고합니다.

## 확인한 방법
- 테스트 5개 추가(월간·연간 남은 일수, 연간 2월 30일 말일 보정, 연간 분할·USD 환산 합계, 환율이 없을 때 USD 분리)
- `npm run verify` 통과(테스트 295개)

## 남은 일·주의
- 구독과 정기 내역은 여전히 따로 관리됩니다. 정기 내역으로 결제 거래를 자동 등록하는 구독은 월말 예측에 이미 들어가므로, 구독 목록까지 합치면 중복될 수 있습니다.
- 환율은 직접 입력하는 값이며 자동으로 갱신되지 않습니다.
