# 동기화 데이터 유실·누출 수정

- 날짜: 2026-11-09
- PR: #28 / 커밋: `9779619`

## 한 줄 요약
저장이 한 번 실패한 뒤 다시 접속하면 다른 데이터가 빈 값으로 덮어써지거나, 로그아웃 후 이전 계정의 내역이 보이던 문제를 고쳤습니다.

## 왜 했나
전체 코드 리뷰에서 동기화 경로의 데이터 유실 버그 7건을 찾았고, 모두 테스트로 재현했습니다. 대표적인 경우는 이렇습니다.
- 오프라인에서 거래 저장이 실패한 뒤 앱을 다시 열면, 원격의 메모·예산·설정이 빈 값이나 기본값으로 덮어써졌습니다. 실패를 표시하는 값이 `'true'` 플래그 하나뿐이라, 재전송할 때 로컬 스냅샷 전체를 조건 없이 올렸기 때문입니다.
- 병합 화면에서 "삭제 후 계속"을 누르거나 충돌 화면에서 "원격 데이터 사용"을 고르면, 남아 있던 플래그 때문에 빈 데이터나 로컬 데이터가 원격을 덮어썼습니다.
- 로그인할 때 병합하면 원격 데이터 안의 정상 기록이 지워졌습니다. 같은 날 같은 금액으로 마신 커피 2잔처럼 내용이 같은 거래가 하나로 합쳐졌습니다.
- 설정을 저장하면 모든 데이터의 기준 버전이 갱신됐습니다. 그래서 다른 기기에서 추가한 메모가 충돌 경고 없이 사라졌습니다.
- 로그아웃 후에도 이전 계정의 캐시가 남아 로컬 모드 화면에 보였고, 다음에 로그인한 계정으로 병합될 수 있었습니다.
- 전체 초기화가 시간 초과되면 화면에는 실패로 보이는데, 원격에서는 초기화가 그대로 진행될 수 있었습니다.

## 무엇을 바꿨나
- 실패 기록에 계정, 실패한 데이터 종류, 실패 당시의 버전을 함께 저장합니다. 재전송할 때는 **실패한 종류만**, 그 사이 원격이 바뀌지 않았을 때만 올립니다.
- 그 사이 다른 기기가 바꾼 데이터는 원격을 따르고, 이 기기의 값은 `hb_backup_*`에 보관합니다.
- 구형 플래그나 다른 계정의 기록은 원격에 올리지 않습니다.
- 병합은 id를 기준으로 하고, 내용이 같은 항목은 로컬과 원격 사이에서만 중복으로 봅니다.
- 일부 데이터만 다시 읽을 때는 그 데이터의 기준 버전만 갱신합니다.
- 로그아웃하면 Firebase 캐시와 실패 기록을 지웁니다. 로컬 모드에서 직접 만든 데이터는 남깁니다.
- 전체 초기화는 원격 초기화가 확정된 뒤에만 로컬을 지웁니다.

## 확인한 방법
- 메모리에서 동작하는 가짜 Firestore로 "저장 실패 → 재시작 → 재전송" 시나리오 테스트 11개를 추가했습니다. 수정 전에는 모두 실패하고, 수정 후에는 모두 통과합니다.
- `npm run verify`를 통과했습니다(테스트 220개).

## 남은 일·주의
- 기존 사용자 기기에 구형 `'true'` 플래그가 남아 있으면, 첫 실행 때 로컬 값을 백업만 하고 원격을 따릅니다. 미동기화 변경은 `hb_backup_*`에 남습니다.
- 병렬 실행 부하로 시간 초과가 나던 ImportModal 첫 테스트에 타임아웃 여유를 줬습니다.
