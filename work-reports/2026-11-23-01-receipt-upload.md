# 영수증 첨부가 저장을 막거나 사진을 잃는 문제 수정

- 날짜: 2026-11-23
- PR: (작성 시점 미정)

## 한 줄 요약
영수증 업로드가 실패하면 거래 저장까지 실패하던 문제, 로그아웃 상태에서 고른 사진이 조용히 버려지던 문제, 지운 거래의 사진이 Storage에 남던 문제를 고쳤습니다.

## 왜 했나
Firebase Storage를 켜기로 하면서(Blaze 요금제 필요, 2026-02-03부터 Spark에서는 Storage 사용 불가) 영수증 경로를 점검했습니다.
- **저장 실패:** 업로드와 거래 저장이 한 `try` 안에 있어서, 업로드가 throw하면 거래도 저장되지 않았습니다.
- **사진 유실:** 업로드 조건이 `receiptFile && auth.currentUser`라서 로그아웃 상태에서는 사진을 골라도 안내 없이 버려졌습니다.
- **고아 파일:** 새 거래의 사진은 `receipt-${Date.now()}` 경로에 올라가는데, 삭제는 `users/{uid}/receipts/{거래 id}`를 지웠습니다. 수정으로 사진을 바꾸거나 지워도 이전 파일이 남았습니다.

## 무엇을 바꿨나
- 업로드가 실패하면 경고 토스트를 띄우고, 거래는 기존 영수증(없으면 없음)으로 저장합니다.
- 로그아웃 상태에서는 사진 선택 버튼 대신 "로그인하면 영수증 사진을 첨부할 수 있어요."를 보여줍니다.
- 업로드할 때마다 새 경로(`generateId()`)를 쓰고, 삭제는 거래에 저장된 다운로드 URL로 합니다. 같은 경로를 덮어쓰면 교체 뒤 이전 URL을 지울 때 새 파일까지 지워지므로 경로를 매번 새로 만듭니다.
- 거래를 수정하면서 영수증을 바꾸거나 지우면 이전 파일을 지웁니다.

## 확인한 방법
- 테스트 3개를 추가했습니다(업로드 실패 시 저장 유지, 로그아웃 안내, 교체·삭제 시 URL 기준 삭제).
- `npm run verify` 통과(테스트 265개).

## 남은 일·주의
- **교수님 작업:** Firebase 콘솔에서 Blaze로 전환하고, Storage 버킷을 무료 사용량이 적용되는 `us-central1`(또는 us-east1/us-west1)에 만듭니다. 그다음 `firebase deploy --only storage`로 `storage.rules`를 배포하고, GCP Billing에서 예산 알림을 설정합니다.
- 이미 `receipt-…` 경로에 올라간 기존 파일은 URL 기준 삭제로 이제 정상 삭제됩니다. 과거에 이미 고아가 된 파일은 정리하지 않았습니다.
