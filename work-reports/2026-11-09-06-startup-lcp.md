# 첫 화면 표시 속도 개선 (LCP 6.0초 → 3.9초)

- 날짜: 2026-11-09
- PR: #33

## 한 줄 요약
앱을 열 때 당장 필요 없는 외부 스크립트(Google 로그인 iframe, Google Analytics)를 뒤로 미루고 폰트 CSS가 첫 화면을 막지 않게 해서, 홈 화면이 뜨는 시간을 약 2초 줄였습니다.

## 왜 했나
- 직전 작업(#31)으로 정적 푸터에 가려져 있던 앱의 실제 LCP가 드러났습니다. 느린 4G 시뮬레이션 기준 약 6.0초였습니다.
- 시작 경로를 분석하니 첫 화면과 관계없는 작업이 앞에 있었습니다.
  - `getAuth()` 기본 설정이 **Google 로그인 팝업용 iframe과 gapi 스크립트**를 앱 시작과 동시에 받았습니다. 이 기능은 Google 로그인 버튼을 누를 때만 필요합니다.
  - Google Analytics(`gtag.js` 약 160KB)가 앱 초기화와 동시에 받아지고 실행돼서 메인 스레드를 두고 경쟁했습니다.
  - 외부 폰트 CSS가 렌더링을 막고 있었습니다(Lighthouse 추정 790ms).

## 무엇을 바꿨나
- Firebase Auth를 `initializeAuth`로 직접 초기화합니다. 로그인 유지 방식(persistence)은 `getAuth()`와 같은 순서 그대로라서 **기존 로그인 세션은 유지**됩니다. 팝업 resolver는 Google 로그인 버튼을 누를 때만 넘깁니다.
- Analytics는 페이지 로드가 끝난 뒤 브라우저가 한가할 때 초기화합니다. 수집은 그대로 유지됩니다.
- 폰트 CSS는 비차단으로 받습니다. 글꼴이 도착하면 바뀌는 방식(`font-display: swap`)은 원래 설정과 같습니다.

## 확인한 방법
같은 Firebase 설정으로 만든 프로덕션 빌드를 Lighthouse 모바일로 5회씩 측정했습니다(중앙값).

| 단계 | 점수 | FCP | LCP | TBT | 요청 수 |
|---|---|---|---|---|---|
| 기존 main | 75 | 1.58s | 6.05s | 174ms | 40 |
| + Auth·Analytics 지연 | 86 | 1.57s | 3.88s | 114ms | 34 |
| + 폰트 CSS 비차단 (최종) | 86 | **1.06s** | 4.05s | 112ms | 34 |

- 폰트 CSS 변경은 LCP에는 영향이 없었지만(오차 범위), 첫 화면이 0.5초 빨리 그려져서 유지했습니다. CLS는 모든 단계에서 0입니다.
- Google 로그인 때 resolver를 넘기는지 확인하는 테스트를 추가했습니다. `npm run verify`를 통과했습니다(테스트 256개).

## 남은 일·주의
- **배포 후 확인 필요:** Google 팝업 로그인이 정상 동작하는지 실제 기기에서 한 번 확인해 주세요. 이메일 로그인과 자동 로그인 유지는 영향을 받지 않습니다.
- **다음 개선 후보:** 첫 화면용 `vendor-firebase`(112KB) 중 약 90KB를 차지하는 Firestore는 로그인하지 않은 사용자에게는 필요 없습니다. 지연 로드하면 추가로 줄일 수 있지만 저장소 계층(`storage.ts`) 전체의 import 구조를 바꿔야 해서 별도 작업으로 분리했습니다.
- 수치는 Lighthouse 시뮬레이션 값이고 실제 기기의 체감 속도와는 다를 수 있습니다.
