# 테마 토큰 도입 (1단계: MonthlyDashboard)

- 날짜: 2026-11-09
- PR: #38

## 한 줄 요약
hex 색상 클래스 대신 쓸 테마 토큰(`bg-surface`, `text-muted`, `bg-tone-blue/15` 등)을 만들고, 가장 큰 파일인 월간 대시보드를 옮겼습니다. 다크 모드는 그대로이고, **라이트 모드에서 안 보이던 글자들이 보이게** 됐습니다.

## 왜 했나
- 기술부채 감사 5번 항목입니다. 컴포넌트에 hex 색상 클래스가 2,202번 쓰였고, 그중 상당수가 라이트 테마를 지원하지 않았습니다.
- 지금 라이트 테마는 `interface.css`가 hex 클래스를 이름으로 하나씩 찾아 덮어쓰는 방식입니다. 이름이 정확히 같을 때만 동작해서 `hover:`나 `/20`이 붙은 변형은 빠지고, 새 hex를 쓸 때마다 다시 깨지는 구조였습니다.
- 월간 대시보드를 라이트 모드로 캡처해 보니 실제로 깨진 곳이 있었습니다.
  - "정기 항목 1건 미등록", "예산 초과 2개 카테고리" 문구가 흰 글씨라 거의 보이지 않았습니다.
  - 결제수단별 잔액(현금·체크·신용) 숫자가 연한 글씨라 밝은 배경에서 흐릿했습니다.
  - 사용할 수 없는 요일, 빈 칸 표시(-)가 다크에서는 흐리게 의도됐는데 라이트에서는 진한 검정이었습니다.

## 무엇을 바꿨나
- **토큰 정의:** `src/index.css`의 `@theme`에 색상 유틸리티를 등록했습니다. 값은 `interface.css`의 CSS 변수에서 오므로 테마에 따라 자동으로 바뀝니다.
  - 의미 토큰(`surface`, `muted`, `accent`, `income`, `expense`, `warning` 등): `interface.css`가 원래 기본 hex 클래스를 바꿔 그리던 변수를 그대로 씁니다.
  - 톤 토큰(`tone-blue/red/green/amber/teal/slate`): 틴트·테두리·링용입니다. 두 테마 모두 원래의 밝은 hex를 씁니다.
  - 글자·중립 토큰(`warning`, `*-pale`, `fg-strong`, `tone-faint`, `tone-hover`, `tone-chip`): 다크에서는 원래 hex를 쓰고, 라이트에서는 읽을 수 있는 값으로 바뀝니다.
- **치환 스크립트:** `scripts/migrate-theme-tokens.mjs`를 추가했습니다. 클래스가 원래 변수로 그려졌는지를 `interface.css`에서 **정확한 클래스명(대소문자 포함)**으로 판정해서, 다크 색이 바뀌지 않는 토큰을 고릅니다. 표에 없는 색은 건드리지 않고 보고합니다.
- **월간 대시보드:** 색상 클래스 341곳을 치환했습니다.
- **재발 방지:** 옮긴 파일에 hex 색상 클래스가 다시 들어오면 ESLint 에러가 나도록 했습니다.
- `CLAUDE.md`의 색상 규칙을 토큰 기준으로 바꿨습니다.

## 확인한 방법
- 샘플 데이터를 넣은 프로덕션 빌드를 Chrome(390×844, 애니메이션 끔)으로 캡처해서 치환 전후를 픽셀 단위로 비교했습니다.
  - **다크:** 의미 있는 차이가 없습니다. 투명도 반올림(`#f252601a` = 10.2% → `color-mix` 10%) 때문에 채널당 최대 1/255 차이만 있습니다. 스파크라인 차트의 한 줄은 CSS만 바꾼 빌드끼리 비교해도 달라지는 빌드 간 렌더링 차이라 이번 변경과 무관함을 확인했습니다.
  - **라이트:** 위에 적은 안 보이던 문구, 흐린 숫자, 흐린 요일·빈칸 표시가 의도대로 바뀌었습니다.
- **설계를 고친 부분:** 처음에는 톤 토큰의 라이트 값을 진한 색으로 정했는데, 캡처해 보니 연한 배경 틴트가 탁하게 변했습니다(초록 카드가 회녹색으로). 그래서 틴트용 톤은 원래의 밝은 색을 유지하고, 글자용 토큰만 라이트에서 진하게 바꾸도록 수정했습니다.
- hex 클래스를 일부러 다시 넣었을 때 ESLint가 에러를 내는 것을 확인했습니다.
- `npm run verify`를 통과했습니다(테스트 262개, 홈 번들 221KB로 변화 없음).

## 남은 일·주의
- **액션 버튼 색(`bg-[#3D8EF8]` 등) 7곳**은 이번에 옮기지 않았습니다. `interface.css`가 배경색과 함께 글자색·hover까지 바꾸고 있어서, 버튼 전용 토큰으로 따로 옮겨야 합니다.
- `style={{ color: '#...' }}`처럼 인라인 스타일로 쓴 색(이 파일에 26곳, 주로 차트·카테고리 색)은 범위 밖입니다.
- 다음 단계: `Analytics`, `TransactionList` → `TransactionModal`, `App`, `ImportModal`, `GoalsView`, `MemoSection` → 나머지 순서로 진행합니다.
- `color-mix`는 Tailwind v4가 원래 요구하는 브라우저(Safari 16.4+, Chrome 111+)에서 동작하므로 지원 범위는 달라지지 않습니다.
